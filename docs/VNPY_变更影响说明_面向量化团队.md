## 🔴 Breaking Changes（必须关注）

### 1. 数据源切换 — 估值数据不再伪造

**影响文件:** `alpha/strategy/industry_rotation.py`

**变更内容:**
- **旧行为:** `PE/PB` 通过 `hash()` 函数随机生成，每次回测结果一致但完全不可信
- **新行为:** 通过 `ValuationFetcher` 从 Tushare/AKShare 获取真实估值数据
  - 优先使用 `alpha/lab` 缓存
  - 未配置 Tushare 时自动回退到 AKShare
  - 支持本地文件缓存（`./cache/fundamental/industry_rotation/`）

**对策略的影响:**
- ⚠️ **回测结果会变化** — 以前的 PE/PB 是假的，现在是真实的，基于估值的选股信号会完全不同
- ⚠️ **需要重新回测** — 所有依赖 PE/PB/股息率的策略都需要重新运行
- ⚠️ **数据延迟问题** — 真实数据有更新延迟，回测时需确认数据时点（避免未来函数）

**行动项:**
- [ ] 确认现有策略是否依赖 PE/PB 数据
- [ ] 重新回测所有估值相关策略
- [ ] 对比新旧回测结果，评估信号差异
- [ ] 确认 Tushare Token 或 AKShare 可用性

**接口变化:**
```python
# 旧代码（已删除）
pe = hash(vt_symbol) % 50 + 10  # 假的
pb = hash(vt_symbol + "pb") / 100 + 0.5

# 新代码
fetcher = ValuationFetcher(cache_dir='./cache/fundamental')
pe, pb, dividend, date = fetcher.get_valuation(vt_symbol)
# 返回真实数据，可追溯到 Tushare/AKShare
```

### 2. 仓位计算逻辑变更

**影响文件:** `alpha/strategy/cross_sectional_engine.py`

**变更内容:**
- **旧行为:** `target_amount = initial_capital × target_position_size`
  - 问题：盈利后总资产增长，但买入金额始终按初始资金计算，仓位比例越来越小
- **新行为:** `target_amount = 当前总资产 × target_position_size`
  - `当前总资产 = 现金 + 持仓市值`

**对策略的影响:**
- ⚠️ **仓位比例会变化** — 盈利后仓位会随总资产增长而增加，亏损后会自动降仓
- ⚠️ **收益曲线会变化** — 复利效应更明显，收益/回撤都会放大
- ⚠️ **风控参数可能需要调整** — 原来的 `position_size` 可能需要重新校准

**行动项:**
- [ ] 确认 `position_size` 参数是否需要调整
- [ ] 重新回测，观察仓位比例变化是否符合预期
- [ ] 检查是否有最大仓位限制逻辑需要补充

**代码对比:**
```python
# ❌ 旧逻辑
target_amount = self.initial_capital * target_position_size

# ✅ 新逻辑
total_assets = self._cash + self._get_total_market_value()
target_amount = total_assets * target_position_size
```

## 🟡 重要变更（建议关注）

### 3. 回测执行细节完善

**影响文件:** `alpha/strategy/cross_sectional_engine.py`

**新增规则:**

| 规则 | 说明 | 默认值 |
|------|------|--------|
| 涨跌停限制 | A 股 ±10% / ST ±5% / 创业板 ±20% | 自动识别 |
| T+1 交易 | 当日买入次日方可卖出 | 启用 |
| 最小交易单位 | 买入数量必须为 100 股整数倍 | 100 股 |
| 滑点模拟 | 成交价格偏离收盘价 | 千一 (0.1%) |
| 流动性限制 | 成交量不足时部分成交 | 启用 |

**对策略的影响:**
- ⚠️ **回测收益可能下降** — 以前能买到的股票现在可能因为涨跌停/T+1/流动性买不到
- ⚠️ **交易频率可能降低** — T+1 限制会减少日内交易机会
- ⚠️ **滑点成本** — 每笔交易增加约 0.1% 的成本
- ✅ **回测更贴近实盘** — 信号更可信，实盘迁移风险更低

**行动项:**
- [ ] 重新回测所有策略
- [ ] 对比新旧回测结果，评估收益/回撤变化
- [ ] 确认滑点/手续费参数是否符合实际交易成本
- [ ] 检查策略是否有依赖日内交易的逻辑

### 4. 股票池扩容

**影响文件:** `alpha/strategy/industry_rotation.py`

**变更内容:**
- **旧股票池:** 申万行业分类 ~479 只/行业
- **新股票池:** 申万行业分类 ~533 只/行业（从 API 动态获取成分股）

**对策略的影响:**
- ✅ **覆盖更广** — 更多股票可选，分散度更好
- ⚠️ **选股结果可能变化** — 同一策略在新股票池中选出的股票可能不同
- ⚠️ **计算量增加** — 更多股票意味着回测时间可能增加（但 P1-4 索引优化已抵消此影响）

**行动项:**
- [ ] 确认新股票池覆盖范围是否符合策略需求
- [ ] 检查是否有需要排除的股票（ST、次新股等）
- [ ] 确认行业分类版本（申万 2021 版？）

## 🟢 透明变更（基本无影响）

### 5. `_get_price` 接口优化

**影响文件:** `alpha/strategy/cross_sectional_engine.py`

**变更内容:**
- **旧行为:** 每天 × 每只股票线性搜索 bars 列表 → O(days × stocks × avg_bars)
- **新行为:** 回测开始时构建 `{date: {symbol: price}}` 索引 → O(1) 查找

**对策略的影响:**
- ✅ **回测速度提升 10x+** — 大股票池回测从小时级降到分钟级
- ✅ **结果一致** — 优化前后回测结果完全相同
- ✅ **接口不变** — `_get_price(vt_symbol, date)` 签名未变

**行动项:** 无需操作，自动享受性能提升。

### 6. 时区处理统一

**影响文件:** 全局

**变更内容:**
- **旧行为:** `datetime.now()` (naive) 与 `datetime.fromisoformat()` (aware) 混用
- **新行为:** 统一使用 `now_utc()` 和 `now_local()` 函数

**对策略的影响:**
- ✅ **无影响** — 仅修复内部时间处理，策略逻辑不变
- ✅ **避免崩溃** — Python 3.12+ 不再抛 TypeError

**行动项:** 无需操作。

### 7. 配置管理统一

**影响文件:** 全局

- **旧行为:** 配置硬编码在各文件中（如 `max_retries=3`）
- **新行为:** 统一从 `vnpy_config.yaml` 读取

**对策略的影响:**

| 指标 | 预期变化 | 原因 |
|------|----------|------|
| 年化收益 | 可能下降 | 涨跌停/T+1/滑点/流动性限制 |

1. **用同一时间段回测** — 确保回测区间一致

3. **记录差异** — 重点关注收益、回撤、交易次数
4. **分析原因** — 如果是预期内的变化（如滑点成本），可接受

## ❓ FAQ

**Q: 我的策略不依赖 PE/PB，是否不受影响？**  
A: 仍受影响。仓位计算变更（Breaking Change #2）和回测细节完善（#3）会影响所有策略。

**Q: 回测结果变化多大算正常？**  
A: 预期年化收益可能下降 1-3%（滑点/手续费/涨跌停限制），回撤可能变化 2-5%。如果变化超过 10%，建议仔细排查。

**Q: 我需要修改策略代码吗？**  
A: 大概率不需要。本次变更主要在基础设施层，策略接口基本保持不变。但建议重新回测所有策略。

**Q: 旧的回测结果还能用吗？**  
A: 不建议。以前的回测基于伪造数据和不完整的交易规则，结果不可信。建议全部重新回测。

**Q: 数据源切换后，回测速度会变慢吗？**  
A: 不会。数据有本地缓存，且 P1-4 索引优化已大幅提升回测速度（10x+）。
