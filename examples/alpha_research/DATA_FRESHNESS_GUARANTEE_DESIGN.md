## 📋 执行摘要

### 当前问题

根据历史数据分析：
- ⚠️ **2026-03-13**: 发现 9 只股票数据陈旧（7-8 天未更新）
- ⚠️ **根本原因**: 数据下载任务未覆盖所有持仓股票
- ⚠️ **影响**: 选股和交易决策基于过期数据

### 设计目标

1. **预防**: 建立多层数据更新机制，防止数据陈旧
2. **监控**: 实时监控数据新鲜度，及时发现异常
3. **告警**: 自动通知到企业微信群，快速响应
4. **修复**: 自动触发数据更新，减少人工干预

## 📊 数据更新策略

### 1. 定时下载（主策略）

**调度时间**:
- **凌晨**: 01:00 - 全量下载（300+ 股票）
- **下午**: 17:00 - 增量下载（持仓股票）

**配置**:
```json
{
  "schedule": {
    "full_download": "0 1 * * *",
    "incremental_download": "0 17 * * 1-5"
  },
  "stocks": {
    "full_pool": 300,
    "holdings": 14
  }
}
```

**保障机制**:
- ✅ 下载失败自动重试（3 次）
- ✅ 下载完成立即验证
- ✅ 验证失败触发告警

### 2. 增量更新（补充策略）

**触发条件**:
- 持仓股票列表变更
- 发现数据陈旧（>2 天）
- 手动触发更新

**更新范围**:
```python
# 增量更新逻辑
def incremental_update():
    # 1. 获取持仓股票
    holdings = get_current_holdings()  # 14 只
    
    # 2. 检查新鲜度
    stale_stocks = check_freshness(holdings, threshold=2)
    
    # 3. 更新陈旧数据
    if stale_stocks:
        update_stock_data(stale_stocks)
        notify_freshness_issue(stale_stocks)
```

### 3. 手动触发（应急策略）

**使用场景**:
- 定时任务失败
- 数据异常需要重新下载
- 临时添加新股

**命令**:
```bash
# 手动触发全量下载
python3 batch_download_enhanced.py --full

# 手动触发持仓更新
python3 batch_download_enhanced.py --holdings

# 手动更新特定股票
python3 batch_download_enhanced.py --symbols 600519,000858
```

## 🔄 自动修复机制

### 修复策略

| 问题类型 | 自动修复 | 重试次数 | 失败后动作 |
|----------|----------|----------|------------|
| 下载失败 | ✅ 自动重试 | 3 次 | 告警 + 人工 |
| 数据陈旧 | ✅ 自动更新 | 1 次 | 告警 |
| 数据异常 | ❌ 不自动 | - | 告警 + 人工 |
| 文件损坏 | ✅ 重新下载 | 2 次 | 告警 |

### 修复流程

```python
def auto_fix_data_issue(issue_type, stock_list):
    """自动修复数据问题"""
    
    if issue_type == 'stale':
        # 陈旧数据 - 自动更新
        result = update_stock_data(stock_list)
        if result['success']:
            notify_complete("数据更新", {"更新股票": len(stock_list)})
        else:
            notify_error("数据更新", result['error'])
    
    elif issue_type == 'download_failed':
        # 下载失败 - 重试
        for attempt in range(3):
            result = download_stock_data(stock_list)
            if result['success']:
                notify_complete("数据下载", {"重试次数": attempt+1})
                return
        # 3 次失败后告警
        notify_error("数据下载", "3 次重试失败")
    
    elif issue_type == 'data_corrupted':
        # 数据损坏 - 重新下载
        delete_corrupted_data(stock_list)
        result = download_stock_data(stock_list)
        if result['success']:
            notify_complete("数据恢复", {"恢复股票": len(stock_list)})
        else:
            notify_error("数据恢复", result['error'])
```

## 💾 数据备份与恢复

### 备份策略

| 备份类型 | 频率 | 保留期 | 存储位置 |
|----------|------|--------|----------|
| 每日快照 | 每天 20:00 | 30 天 | `data/snapshots/` |
| 每周备份 | 每周日 | 90 天 | `data/backups/weekly/` |
| 每月备份 | 每月 1 日 | 365 天 | `data/backups/monthly/` |

### 备份内容

```
data/
├── snapshots/           # 每日快照
│   ├── 2026-03-18/
│   │   ├── bars/       # K 线数据
│   │   ├── fundamentals/ # 财务数据
│   │   └── metadata.json # 元数据
│   └── ...
├── backups/
│   ├── weekly/         # 每周备份
│   └── monthly/        # 每月备份
└── archive/            # 归档数据（>1 年）
```

### 恢复流程

```bash
# 1. 列出可用快照
python3 data_recovery.py --list

# 2. 验证快照完整性
python3 data_recovery.py --verify 2026-03-18

# 3. 恢复到指定日期
python3 data_recovery.py --restore 2026-03-18

# 4. 验证恢复结果
python3 data_freshness_monitor.py --check
```
